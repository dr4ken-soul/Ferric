# Ferric

Your AI feature has no test suite. Ferric is the one it should have had.

Ferric records normalised LLM and agent interactions as reviewable JSON cassettes, then replays matching requests locally for behavioural regression tests.

## The problem

Model output is non-deterministic, so exact string assertions fail when wording changes. Live model calls make CI slower, cost money and can fail because of provider availability or rate limits. Prompt and model changes can therefore alter tool use, critical arguments or structured output without a focused regression failure.

## 60-second offline quickstart

Requirements are Python 3.11 or later. Run these commands from a Ferric source checkout. They use the committed deterministic local demo fixture and need no provider SDK, API key or network.

On macOS, Linux or Git Bash:

```bash
python -m pip install -e ".[dev]"
FERRIC_MODE=replay python examples/demo-agent/agent.py
FERRIC_MODE=replay python -m pytest -q
python -m ferric.cli verify --cassette-dir tests/cassettes
```

On PowerShell:

```powershell
python -m pip install -e ".[dev]"
$env:FERRIC_MODE = "replay"
python examples/demo-agent/agent.py
python -m pytest -q
python -m ferric.cli verify --cassette-dir tests/cassettes
```

Expected results at the current revision are three local MCP-shaped tool calls, `114 passed`, and `Verified 4 cassette(s). Schema, hashes and redaction passed.` The fixture was generated by [`scripts/generate_fixtures.py`](scripts/generate_fixtures.py) from deterministic local payloads. It is not provider traffic and it is not Kiro production capture.

## Record and replay

Wrap a supported synchronous client and keep the normal SDK call shape:

```python
import ferric

client = ferric.wrap(client, cassette_dir="tests/cassettes")
response = client.chat.completions.create(
    model="gpt-4.1-mini",
    messages=[{"role": "user", "content": "Review March"}],
    tools=[],
)
```

Set `FERRIC_MODE=record` to call the provider and write a redacted cassette. Leave it unset for passthrough. Set it to `replay` to require an exact local fingerprint match.

**Replay has an explicit no-socket guarantee.** The replay branch does not call the provider endpoint or retain a live fallback. A missing fingerprint raises `UnmatchedRequestError` with the nearest cassette diagnostic. The test suite patches `socket.socket` to fail on use and supplies a provider endpoint that also fails if called. Repeated replay returns the same stored response data. Replay itself requires no provider key and incurs no provider token spend.

## Behavioural assertions

Load a validated cassette before applying assertions:

```python
from pathlib import Path

from ferric.schema import Cassette

cassette = Cassette.model_validate_json(
    Path("tests/cassettes/7390cec8b7a3c6af2cc1e019ae3d62d2ac8115c18451dc1f22669247c65c9fd2.json").read_text()
)
```

### Tool sequence

Compares ordered tool names and reports the first divergent index.

```python
from ferric import assert_tool_sequence

assert_tool_sequence(
    cassette,
    ["read_ledger", "flag_anomalies", "prepare_review"],
)
```

### Critical arguments

Compares only declared fields. Dot-separated paths address nested fields. Other arguments are ignored.

```python
from ferric import assert_tool_arguments

assert_tool_arguments(
    cassette,
    "prepare_review",
    {"month": "2026-03"},
)
```

### Response schema

Checks the implemented JSON Schema subset and reports the failing JSON path.

```python
from ferric import assert_response_schema

assert_response_schema(
    cassette,
    {
        "type": "object",
        "required": ["anomalies"],
        "properties": {"anomalies": {"type": "integer"}},
    },
)
```

### Leakage

Scans the stored outbound request, user events and tool results. A failure reports the pattern name and safe location, not the matched value.

```python
from ferric import assert_no_leakage

assert_no_leakage(
    cassette,
    {"private_identifier": r"private-[0-9]+"},
)
```

`assert_refusal(cassette, expected=True)` is also available for refusal checks and drift classification. The four documented assertion families are sequence, arguments, schema and leakage.

## Cassette commands

The default cassette directory is `tests/cassettes`. Use `--cassette-dir` to select another store.

```bash
ferric list --cassette-dir tests/cassettes
ferric verify --cassette-dir tests/cassettes
ferric promote 7390cec8b7a3 --cassette-dir tests/cassettes --output-dir promoted-tests
```

`list` validates the store and prints cassette IDs, providers, models and event counts. `verify` checks schemas, content hashes, the manifest and built-in redaction patterns. `promote` copies a trace through the redacting store boundary and writes a runnable pytest file with defaults derived from available evidence.

Drift is the one networked workflow:

```bash
python -m pip install -e ".[openai,anthropic]"
ferric drift --to TARGET_MODEL --cassette-dir path/to/cassettes --html drift-report.html
```

It calls the provider represented by each OpenAI or Anthropic cassette, classifies results as `unchanged`, `reworded` or `diverged`, names tool selection, tool order, schema validity or refusal changes, and totals provider-reported tokens. Install the relevant provider extra and configure the provider SDK's normal credentials. MCP cassettes are reported as unsupported and excluded from live classifications because this command has no target MCP server integration.

The committed [sample drift report](examples/sample-drift-report.html) is a self-contained HTML file with no external resources. Its rows come from three deterministic local drift fixtures and its 614-token total is fixture metadata produced by `scripts/generate_fixtures.py`. It is not evidence of a live drift run. No live drift run has been performed for this repository.

## Limitations

- Token-by-token streaming capture is not provided. The intended cassette form is one coalesced assistant message, but streaming client paths are not implemented.
- Embeddings, image generation and audio endpoints are not supported.
- There is no hosted service, dashboard or account system.
- Assertion generation is limited to the defaults written by `promote`.
- Multi-turn conversation branching and replay of divergent paths are not supported.
- No provider beyond OpenAI, Anthropic and MCP tool calls is supported. The runtime wrapper supports OpenAI `chat.completions.create` and Anthropic `messages.create`; MCP currently has a normaliser and local fixture reader, not a wrapped live client.
- The wrapper covers synchronous `create` calls. It does not preserve every concrete provider response class, although it reconstructs common attribute access and serialisation methods.
- Response schema checks cover `type`, `enum`, `required`, `properties` and `items`. They are not a complete JSON Schema implementation.
- The live drift path exists but has not been exercised against provider services in this repository. Provider failures, credentials and model compatibility remain environment-dependent.
- The committed demo and report use deterministic local evidence. There is no demo video URL and no Kiro production capture.
- The web application builds, but this revision has no browser automation or committed responsive and accessibility test results.

```bash
python -m pytest -q
python scripts/check_offline.py
python scripts/check_redaction.py
python -m pytest tests -q -k "schema or adapter or golden"
python -m ruff check .
python -m mypy
```

Package and CLI commands:

```bash
python -m pip install -e ".[dev]"
ferric --help

```

```bash

npm install

```

`npm run build` runs the redaction gate, regenerates cassette-derived site data, type-checks the application and writes the static build to `web/dist`, including a direct `/docs/` entry point. The current observed lint, type-check, production build and audit commands exit successfully.

## Vercel deployment

The site is static. It does not need a database, serverless function, API key or Vercel environment variable.

The simplest Vercel setup uses these project settings:

```text
Root Directory: web
Framework Preset: Vite
Install Command: npm ci
Build Command: npm run build:vercel
Output Directory: dist
```

The repository also includes a root [`vercel.json`](vercel.json) for importing the repository without changing Root Directory. That path installs from `web/package-lock.json`, builds the same Node-only static bundle and publishes `web/dist`. The generated cassette data is committed and is therefore available to Vercel without installing the Python package.

## Live drift credentials

Live drift is a local developer workflow. It is not used by the website or by the Vercel build. The CLI reads these variables from the shell or from the ignored root `.env` file:

```dotenv
OPENAI_API_KEY=your-openai-key
ANTHROPIC_API_KEY=your-anthropic-key
GROQ_API_KEY=your-groq-key
```

Use an OpenAI key from <https://platform.openai.com/api-keys>, an Anthropic key from <https://console.anthropic.com/settings/keys>, or a Groq key from <https://console.groq.com/keys>. Groq uses its OpenAI-compatible API with `GROQ_API_KEY`, not `OPENAI_API_KEY`. You only need the provider matching `ferric drift --to`.

Never commit `.env` or put these keys into Vercel. The static site has no code path that needs them.

Ferric itself runs without any provider key in passthrough, replay and offline test modes. A key is only needed when you explicitly run live `ferric drift` against a provider. The current Vercel deployment is a static landing and docs site. It does not record model traffic from a deployed application.
